# 试讲视频模块

学生从“AI 实时评估 → 上传视频”选择本地视频，先进行 AI 评估，无需填写视频详情。综合评分达到 80 分时弹窗询问是否上传；选择“是”后才填写试讲课题和学科，确认上传即公开展示，无需选择公开或私密，也可暂不上传并保留当前评估报告。评估完成后可从报告主动打开上传表单；确认上传才保存到“我的上传”，服务端核验评估任务归属与文件哈希并复用报告，不重复调用 AI。公开前必须填写课题及学科，公开区显示账号真实姓名和学院，不返回成绩、报告、班级、学号或存储路径。不录制或发布摄像头练习。历史私密视频不会自动公开。

学生端“试讲学习”包含“优秀试讲示例”“同学试讲”和“我的上传”标签。老师端保留“学生自主试讲”查看所指导学生的视频，不新增“试讲学习”入口。优秀示例按学科分组，并区分教师示范、学生示范，由管理员在“试讲视频管理”上传、编辑、上下架或删除，优秀示例不设评论区。

“同学试讲”使用 16:9 图片封面，下方白色卡片展示学科、课题、试讲内容、真实姓名和学院，不在封面叠加个人资料。姓名与学院直接读取账号资料。“试讲学习 → 我的上传”可以管理个人视频，本人发布的公开视频卡片也直接提供删除按钮；删除后立即从同学试讲中移除，分析报告保留。删除权限仍由服务端核验。封面按需从视频提取并缓存，优先使用 FFmpeg，没有可用的 FFmpeg 时使用 OpenCV；提取失败显示默认课堂图片。封面请求沿用视频权限校验，原视频删除或到期时同时清理缓存封面。

学生打开同学上传的视频后，播放器下方展示“评论交流”。仅已登录且有视频观看权限的学生可发表评论，老师端不展示评论区，服务端同时拒绝老师读取、发表和删除评论。管理员保留查看和删除评论的管理权限，不提供发表评论功能。评论保存到数据库，按时间倒序分页展示，每页 20 条。评论显示账号真实姓名、身份和发布时间，不显示头像；上传者标注“作者”。输入支持换行及 Ctrl + Enter 发表，每条最多 1000 字，拒绝空白评论，内容按纯文本展示。学生可删除自己的评论，视频上传者不能代替其他评论者删除评论。评论列表提供刷新按钮。

评论接口每次都重新检查视频权限，改为私密后仅学生本人和管理员可访问评论；对应老师仍可观看视频，但无评论权限。视频到期、删除或下架后停止评论访问与发表。新表 `trial_video_comments` 随现有启动建表流程创建，不修改已有视频记录。

## 权限与保留

- 新视频存入 `private_trial_videos`，必须位于公共 `UPLOAD_DIR` 之外。
- 私密视频仅本人、所关联批次中当前分配的指导老师、管理员可看。学生无需填写批次：优先关联最新进行中的已分组批次，其次历史分组，再其次最新进行中批次；没有可关联批次时留空，没有分组时不授予任何老师私密访问权。
- 播放先通过登录接口取得限定视频、限定用户的一小时凭据。每个播放与 Range 请求重新检查账号状态及当前可见范围，改为私密、删除、下架或调整指导老师后，旧凭据不能绕过权限。凭据使用独立签名密钥，不能作为系统登录令牌。
- 私密视频保留15天；从公开改为私密时开始计算15天。小时清理任务和上传前清理会释放到期原文件；到期时即停止播放，不必等下一次清理任务。公开视频及管理员优秀示例不自动过期。
- 删除或到期清理只移除原视频，持久化的分析报告保留在个人列表中；报告始终仅本人、对应老师、管理员可读。
- 管理员下架学生视频时记录原因，并记录“上传者 + 文件 SHA-256”的禁公开标记。同一用户删除后重新上传同文件也不能再次公开。
- 现有作业提交、旧实时评估临时视频不自动导入新库。新表随应用启动通过现有 `create_all` 流程创建，不修改既有作业表。

## 容量配置

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `TRIAL_VIDEO_STORAGE_DIR` | `./private_trial_videos` | 私有视频文件目录 |
| `TRIAL_VIDEO_MAX_BYTES` | `1073741824` | 单文件最多1 GB |
| `TRIAL_VIDEO_USER_BYTES` | `1073741824` | 每名学生累计最多1 GB |
| `TRIAL_VIDEO_TOTAL_BYTES` | `21474836480` | 新视频库总额度，暂定20 GB，部署前按实际空余磁盘调整 |
| `TRIAL_VIDEO_MIN_FREE_BYTES` | `268435456` | 保存时预留至少256 MB磁盘空间 |
| `TRIAL_VIDEO_PRIVATE_DAYS` | `15` | 私密原视频保留天数 |

流式分块写入文件并计算哈希；个人额度包括公开、私密的未删除文件，全站额度包括学生视频及管理员示例。配额检查与上传写入串行执行，避免同时上传穿透额度。当前应用沿用单后端 worker 部署；扩展到多进程、多副本前，应改为共享锁及共享存储预留机制。

Docker Compose 新增独立持久化卷 `trial_videos_data`；备份时需要同时保存数据库和此卷。Nginx API 请求体限制为1100 MB，为1 GB文件及 multipart 封装留出余量。若外部还有反向代理，也应同步提高上传限制和超时。播放器建议使用浏览器兼容的 MP4/WebM，不新增转码服务。新增页面和接口不修改既有作业上传的500 MB限制。

视频分析结果会持久化，新视频的后台分析串行执行，避免同时调用造成资源峰值。运行中的分析若遇服务重启，会标记为中断并说明原因，已保存视频仍可观看；如需重新分析，可清理原视频后重新上传。已有报告不随原视频删除。比赛部署前可用小文件先验证实际分析服务及带宽。

视频处理优先使用系统 FFmpeg，未配置时使用后端依赖 `imageio-ffmpeg` 自带的可执行文件；无需单独安装 ffprobe。外部程序通过工作线程调用，兼容 Windows 下 Uvicorn `--reload` 的 SelectorEventLoop，避免上传成功后评估立即因 `NotImplementedError` 失败。

## 验证

在 `backend` 下运行：`.venv/Scripts/python.exe -m pytest tests/test_trial_videos.py -q`。

在 `frontend` 下运行：`npm run build`。

Windows 视频处理回归：`.venv/Scripts/python.exe -m pytest tests/test_video_media_tools.py tests/test_trial_videos.py -q`，包含真实视频生成、时长读取、音轨提取和截图验证。
