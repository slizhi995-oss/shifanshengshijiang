# 教材知识库与教案生成设计方案

日期：2026-10-07。当前状态：章节正文检索、章节确认、素材数据库、教案自动配图已实施。最新提供的 `物理必修第一册.pdf` 有 134 页及文字层；已导入全书页码正文、103 张原图候选，并发布核对过的“牛顿第一定律”（PDF 88–92 页，印刷页 83–87）与 4 张教材原图。版次、印次和 ISBN 仍待管理员核对。

## 本次实现与早期规划的区别

- 数据库保存教材元数据、逐页正文、已核对章节、图片标签与关联、教案内容和来源。PDF/图片保存在私有文件目录，由数据库路径关联，登录后按权限读取；不把二进制图片存进 SQL 表。
- 首版以用户确认的小节为检索边界，读取完整小节正文，最长 48,000 字符；过长需管理员拆分。正文送给现有文本模型，同时保留原教案模板提示词。
- 模型提出 `[[图片：具体对象、图号及教学用途]]`；程序从同书同章节的已核对图片中按图号、标签和描述检索。明确图号时限定该图候选，再由文本模型根据实际教案上下文、图片说明和适用条件选择，允许返回空结果；不能仅因图号命中就忽略物理条件。程序核验 ID 后插入规范 Markdown 图片链接。
- 教案预览登录取图；下载“教案及图片”得到含相对图片路径的 ZIP。
- 原图缺失时教案保留“图片待插入”，供使用者补充素材。
- **当前没有安装 Qdrant、配置嵌入模型或实现向量/混合检索。** 完整小节检索避免首批样本因截取片段丢失定义前提、题目条件；向量检索仍是全书跨章节检索扩展方向，不属于本次实现成果。
- 教材模式暂不流式返回，先完成配图再返回完整教案。通用教案保留原接口兼容性，由用户明确切换。

使用、接口和验证说明见 [教材数据库与配图链路运行说明](教材数据库与配图链路运行说明.md)。下面保留早期设计讨论，其中 Qdrant、OCR、题目级关联、向量分块和连续多章节选择等仍是后续规划，不能视作已实现功能。

## 早期设计讨论（规划记录）

## 已确定的产品范围

1. 管理员统一上传教材 PDF，管理教材信息和解析结果。
2. 首版以高中物理的一套教材验证流程与效果，后续扩展到其他学科、年级和版本。
3. 系统根据年级、学科、课题推荐教材及章节，用户确认后才用于生成教案。
4. 知识、定义、公式和教材原题忠实于教材。模型可以设计导入、活动与提问；新增练习明确标为“补充练习”，不得冒充教材原题。
5. 没找到匹配教材、章节，或者教材解析/检索不可用时，提示重新选择。用户主动切换后，才使用现有通用方式生成；不得静默回退并声称参考了教材。

## 功能方向

管理员流程：上传教材 → 填写并核对版本信息 → 解析正文、目录与页码 → 查看解析样本并修正问题 → 建立检索索引 → 发布可用教材。

用户流程：填写年级、学科和课题 → 在“教材依据”区域查看推荐教材/章节 → 确认或更换章节 → 检索对应教材内容 → 将相关段落与现有教案提示词共同送入模型 → 生成教案并展示教材出处。

推荐结果应展示书名、出版社/版本、册次、章节和页码。生成前可查看教材内容摘要。生成后保留本次确认的教材、章节与使用片段，便于核对与重现；同一课题存在多个版本时，不由语义相似度自动决定版本。

首版允许明确选择一章或与当前课题相关的连续章节，检索限定在用户确认的范围内。章节内容较短时使用完整相关小节，较长时检索若干相关片段及必要上下文，不能因只取高相似度段落而丢失题目条件、定义前提或相邻结论。

## 教材与教案的关联建议

用户本轮提出把教材检索和自动配图连成一个流程，以减少自由生成教案后再搜集图片的工作量。推荐方向为：教材章节（正文、题目与图片关联）→ 检索确认章节及可用材料 → 生成带来源和图片引用的教案。本文补充设计建议，尚未实现。

教材导入时同步整理正文、图号、图注、原题及其图片，关联稳定的教材、章节、内容片段、题目与素材身份。原始 PDF 页序号及裁剪位置用于核对；不是把文字和图片分别入库后再完全依赖语义猜测来建立关系。

生成教案时，教材上下文同时包含可用素材清单：素材 ID、对应段落或题目、图意、用途与必要条件。模型依据教材和现有教案提示词设计教学过程，优先复用可用材料。知识、定义、题目条件不随生成变化；导入、提问和活动组织可以变化，新增练习仍按既有约定标为补充练习。

在可读教案之外，后台保留每个教学环节使用的教材内容片段、题目及素材引用。引用必须指向本次实际提供的材料，并由程序核验，不能只靠正文中一句「展示教材图片」或模型自行编写的图号。

同章节的图片不能任意互换，图示使用条件必须与教案一致。可用素材帮助组织活动，不得为了凑图改变教学目标、物理条件或教材事实。新增活动可使用文字指令、实际实验或已支持的原生教学图形；暂未覆盖的配图需求继续明确占位。

用户编辑教案后，对应引用须重新核验。改变题目、物理条件或活动目的时，旧图片引用可能失效，不能仅凭相同教学环节位置继续套用。

首版收集材料以用户提供的教材 PDF 和确认的代表章节为起点，先从章节中整理原图；仅对实际未覆盖的必要情境补充少量照片。实际能提取多少图、哪些图需裁剪或核对，拿到 PDF 后通过样本确认。

## 技术方向

首版默认采用 Qdrant 自托管服务保存向量索引，与现有 Docker Compose 部署方式配合。保留现有关系数据库，保存教材目录、版本、章节、解析任务、文本片段与生成引用；原始 PDF 和解析文件保存在后端私有目录。向量索引可以重建，不作为教材原文的唯一存储。

检索采用教材/版本/章节精确筛选，加关键词与向量检索，必要时再排序。先约束教材范围，再比较语义相关性，避免不同版本和年级的相似内容混入结果。关键词检索需要验证中文术语、公式符号和章节名称的实际效果，不能把简单字符串包含当成完成了混合检索。

新增独立的嵌入模型配置与调用接口；教案生成继续使用现有文本模型。嵌入模型的具体供应商、模型和维度在拿到教材样本后，结合可用 API、解析质量和检索效果确定。记录嵌入模型及分块规则版本，更换模型时重建对应索引，不能混用不同维度或不同模型的向量。

依据：[Qdrant 本地部署](https://qdrant.tech/documentation/quickstart/)、[元数据过滤](https://qdrant.tech/documentation/search/filtering/)、[混合检索](https://qdrant.tech/documentation/search/hybrid-queries/)。这些能力支持本方案的部署和检索结构，不代表尚未测试的教材检索质量已得到保证。

## 教材解析与来源

- 接收 PDF 后先检查封面、目录、正文、公式、例题、习题及包含教学图的代表页面，再确定解析方案。文字 PDF 优先抽取原始文字；扫描 PDF 使用 OCR。现有 `document_parser.py` 只有文字抽取，不能直接当作完整教材解析器。
- 每个片段绑定教材 ID、版本、章节、PDF 页序号与可识别的教材印刷页码。两种页码分别记录，避免封面、目录导致引用页码错位。
- 按章节、小节、知识段和题目语义组织片段；保留完整定义、公式条件、题干、选项和可关联的解答，不按固定字符数生硬切断。
- 表格、公式和依赖插图的题目须保留结构与原页定位。暂时无法可靠解析的材料明确标记，不允许模型凭空补全图示信息或题目条件。
- 导入任务记录状态与错误；管理员核对后才发布。再次上传或替换版本时保留明确的版本身份，避免旧索引与新原文混用。

## 教案生成约束

现有科目、年级、课题、时长、重难点、教案模板和生成模型继续使用。教材内容提供知识依据，现有教案提示词继续决定教学组织、格式与输出要求。

教材作为参考资料传入，不能执行资料中改变系统规则的指令。普通生成与流式生成共用教材上下文构建逻辑，保持相同的来源范围和内容边界。

知识和教材原题应关联实际检索到的片段；出处由程序核验教材、章节及页码，不能接受模型虚构的引用。模型生成的活动和补充练习单独标识，补充练习及答案需要内容正确性检查，不能因为标为补充就免除校验。

生成记录区分“已参考教材”和“通用生成”。教材服务故障、检索结果不足或目录匹配不明确时，停止教材生成并显示原因，由用户决定重新选择或主动切换通用生成。

## 现有代码的接入位置

- `frontend/src/views/student/AIGenerator.vue`：新增教材依据区域、推荐结果、章节确认与来源展示。
- `frontend/src/stores/aiGenerator.ts` 和 `backend/app/api/routes/ai.py`：传递并校验确认的教材/章节，进入教材检索流程。
- `backend/app/services/ai_model_service.py`：普通与流式教案生成共用上下文与提示词构建。
- 管理端新增教材管理；可复用通用上传能力，但教材原文须持久保存，不能使用当前上传模板后抽取文本并删除原文件的生命周期。

## 实施与验收顺序

1. 拿到首批 PDF 后完成解析样本和目录核对，确认教材版本与页码映射。
2. 完成教材导入、管理员检查、发布和检索，先检验“找得到正确版本、章节与原文”。
3. 接入教案页面的推荐/确认流程，以及普通和流式生成；检验知识、原题、补充内容标识与来源。
4. 使用同一教材的多个课题及明确不在教材中的查询验证，检查匹配准确性、引用可追溯性、检索失败提示和通用生成的主动切换。
5. 教案生成稳定后再扩展教材范围；图片素材按章节核对。已提供的教材共 120 页、没有文字层，需要 OCR 后核对章节正文、公式和原题，再接入教案检索。

本轮只保存设计方向，没有导入教材、配置嵌入模型、安装向量数据库或修改现有生成接口。
