# OpenMAIC 借鉴与升级建议

分析日期：2026-10-03。

本建议对照本地 `D:\27计算机设计大赛\OpenMAIC-main` 和当前试讲系统的代码形成。只进行了静态阅读，没有启动 OpenMAIC、调用模型或验证两个项目的运行效果。下文明确区分参考项目已有设计与建议新增的功能；复杂度是相对判断，不是工期承诺。

## 一、推荐方向

建议把当前项目进一步发展为“师范生备课、课堂演练、证据反馈和针对训练的平台”。OpenMAIC 的 AI 教师主要帮助用户学习课程；在本项目中，师范生是试讲教师，AI 主要扮演学生和训练教练。因此，发言调度、提示方式和评价目标需要适配这个角色关系。

| 优先级 | 功能 | 当前基础 | 新增价值 | 相对复杂度 |
|---|---|---|---|---|
| P0 | 课堂配置、结果真实性与记录保存 | 模拟课堂、流式对话、后端练习会话接口 | 让现有设置生效，可靠记录真实训练 | 低至中 |
| P1 | 虚拟课堂：角色状态与发言调度 | 四名模拟学生、课堂即时评分 | 连贯的学生反应、点名、追问和课堂应变训练 | 中至高 |
| P1 | 教案生成教学资源包 | 教案生成、模板上传和内容下载 | 同时生成板书、随堂题和教学环节 | 中至高 |
| P1 | 问题驱动的专项训练 | 成长画像、学习路径、练习报告 | 让评价产生可执行任务，并验证改进 | 中 |
| P2 | 教材与课标知识库 | PDF/Word 解析、资源中心 | 带来源的备课与诊断依据 | 中至高 |
| P2 | 多视角教案评审 | 教案分析、教师批改、评分规则 | 按学科、教学设计、学情和板书分别检查 | 中 |
| P2 | 课堂事件回放与再演练 | 对话回放、视频诊断播放器 | 定位“哪次回答出现问题”，重新演练同类场景 | 中至高 |

## 二、先补齐现有功能的连接

### 1. 让课堂配置真正影响模拟

`frontend/src/views/student/AIAssistant.vue` 已有教学方式、班级规模、训练重点、互动方式和难度设置。但启动练习和发送对话时，当前请求主要传递教案、年级、性格、模型与对话历史；上述设置没有进入对话请求。`backend/app/api/routes/ai.py` 的对应请求模型也没有这些字段。

建议先贯通前端参数、后端校验、角色提示和会话保存。班级规模应改变模拟的参与分布与事件频率，难度应改变学生困惑和追问层次，训练重点应影响反馈维度。界面上的不同选项必须产生可解释的行为变化。

### 2. 保存实际训练过程

备课助手页面目前主要通过 localStorage 保存会话；后端已经有 `practice_sessions.py` 和 `PracticeSession`，应优先接通现有持久化接口。新增功能应围绕服务端会话 ID 组织，保存配置、消息、事件和报告。课堂模板与个人训练记录分别保存，复用模板时不能带入其他学生的历史。

### 3. 展示真实服务状态

当前备课助手在三秒内未收到首个输出时，会中止请求并填入预置回复。真实训练建议改为展示等待状态，并提供取消和重试；演示回复应有清晰标识，不能成为真实训练评分的依据。先解决这一点，才适合进一步增加多角色调度和模型调用。

## 三、虚拟课堂：最有辨识度的升级

参考来源：

- `OpenMAIC-main/lib/orchestration/director-graph.ts`：导演决定下一个发言角色，一次请求最多执行一个导演到角色的生成周期。
- `OpenMAIC-main/lib/orchestration/registry/types.ts`：角色定义、人物设定与角色可用动作。
- `OpenMAIC-main/lib/orchestration/summarizers/`：对话摘要、角色上下文与白板动作记录。
- `OpenMAIC-main/lib/prompts/templates/agent-system-wb-student/system.md`：学生在被邀请时才使用白板。

当前基础：`backend/app/services/ai_prompts.py` 的 `CLASSROOM_SIMULATION_PROMPT` 让一次模型回复同时扮演小明、小红、小刚、小美；前端通过文本标记辨认角色。已有多角色表现，但尚未形成独立角色状态和调度流程。

建议设计：

1. 为每名虚拟学生保存已理解知识、未解决困惑、典型错概念、参与状态和个人对话摘要。
2. 增加课堂调度器，先判断是点名、开放提问、追问、讲解还是小结，再选择合适学生反应。
3. 每轮通常只生成一名学生的主要反应；有必要时增加同伴反应。多角色不必每轮全部调用模型。
4. 用明确的消息和事件结构返回角色 ID、发言内容、举手、理解变化及反馈依据，逐步替代依赖角色名字和标签的文本解析。
5. 保留师范生的课堂主导权。虚拟学生提出问题后，应等待师范生回答；教练在请求帮助或练习结束时给出提示。

适合加入的场景：学生答错、一直沉默、概念混淆、追问原因、课堂讨论偏题、分心，以及时间不足时如何收束。

示例：讲“三角形面积”时，小红误以为面积等于底乘高。师范生讲解后，系统记录她是否纠正了这一误解；小美是否理解，应通过点名或新问题确认，不能因为另一个学生答对就认定全班理解。

第一版验收：同一角色连续几轮保持知识状态；点名后正确角色回应；未解决问题不会自动消失；调度器不会用 AI 教师代替师范生讲课；刷新后可以恢复会话和报告。

## 四、教案生成教学资源包

参考来源：

- `OpenMAIC-main/lib/types/generation.ts`：材料和需求先生成大纲，再生成场景。
- `OpenMAIC-main/packages/@openmaic/generation/README.md`：内容生成、动作生成和场景组装可以分别执行。
- `OpenMAIC-main/packages/@openmaic/dsl/README.md`：统一描述场景、幻灯片、测验、白板动作，并提供结构校验。
- `OpenMAIC-main/lib/server/agent-runtime/dsl-tools.ts`：局部修改按操作应用并校验，一组操作成功后才保存。

当前教案生成主要产出文本，并提供 Markdown 下载。建议加入“教学资源包”概念，包含教学目标、环节与时间、教案正文、板书方案、随堂题、答案与解析，以及预期学生困惑。

操作流程：选择教材或输入课题 → 生成环节大纲 → 用户调整顺序和时长 → 分环节生成资源 → 预览并局部修改 → 用于课堂演练和导出。

第一版采用板书预览和题目表单，优先支持文本、图片和公式。用户可说“把导入改成生活情境”“给这个环节增加一道检查题”，系统只修改相关环节，并保留上一版本。

把题目和练习会话关联到同一资源包版本。资源包改动后，已有练习报告仍引用当时的版本，避免评价依据漂移。

验收重点：目标、环节和题目一致；总时长可检查；修改一个环节不覆盖其他环节；生成失败允许单独重试；实际导出内容与预览一致。

## 五、问题驱动的专项训练

参考来源：

- `OpenMAIC-main/lib/pbl/v2/runtime/learner-state.ts`：里程碑、微任务、提交、评价和参与事件独立记录。
- `OpenMAIC-main/lib/pbl/v2/prompts/evaluator-milestone.md`：反馈引用实际行为与事件证据。
- `OpenMAIC-main/eval/zone-of-proximal-development/README.md`：检查独立尝试、受助练习和新任务复核，避免提前透露答案或将重做成功当成首次独立表现。

本项目的迁移目标是教学能力训练。可加入“导入设计、概念讲解、追问引导、处理错答、课堂管理、时间收束”等三至五分钟练习。

从 AI 报告的问题卡直接创建训练任务，关联问题证据、目标维度和评分规则。练习中允许用户主动获取提示，结束后用新的同类场景复核。报告分别标注独立完成与在提示下完成。

示例：发现师范生直接纠正学生答案、缺少追问 → 安排处理错答练习 → 练习期间提示如何追问 → 新场景独立复核 → 检查是否先探查学生思路、再引导修正。

成长画像先展示任务完成、可追溯的具体行为变化与教师确认。同一维度的前后对比使用一致的评分规则，并记录规则版本；不把两次模型打分上涨直接解释为学习效果已经得到证明。

## 六、教材与课标知识库

参考来源：

- `OpenMAIC-main/lib/rag/types.ts`：知识片段带来源、页码、章节、版本和作用域。
- `OpenMAIC-main/lib/rag/ingest/` 与 `lib/rag/chunking/`：材料进入系统后按结构拆分。
- `OpenMAIC-main/lib/rag/providers/in-memory-lexical-index.ts`：本地已有的是词法检索实现，其能力声明为 `vector: false`，不能视为现成的生产向量知识库。

当前资源推荐会将最多五十条资源的标题和标签等信息提供给模型；建议继续深入到经过教师审核的教材正文、课标条目、优秀教案和案例片段。

建议按学科、年级、教材版本和课程授权筛选后检索。生成教案和反馈时引用相关片段，显示文件、章节和可定位页码；没有检索依据时明确提示。第一版可用关键词与元数据检索，后续根据真实检索效果再增加向量检索。

适合的学生体验：“这条教学目标依据什么？”可以打开引用材料；“我的讲解哪里不准确？”可以看到教案片段和对应参考内容。

## 七、多视角教案评审与课堂回放

### 多视角教案评审

借鉴多角色职责划分，新增学科准确性、教学设计、学情适配和板书表达四种检查视角。该用途是对 OpenMAIC 调度思想的扩展，不是它已有的师范生教案评审功能。

各视角只返回所属范围的问题、证据和修改建议，由汇总步骤去重并标注分歧。第一版可先做两种视角，用户选择按需执行。教师使用现有评分规则作最终批改，多个视角的分数不简单平均。

### 课堂事件回放

参考 `OpenMAIC-main/lib/choreography/timeline.ts` 和 `packages/@openmaic/dsl` 的动作序列。记录角色发言、教师回应、题目展示、白板操作和反馈的时间线。

现有 `VideoDiagnosisPlayer.vue` 已有片段定位、字幕和关键时刻；应在它的基础上关联课堂事件，而不是重复建一个播放器。先做文字课堂事件回放，再关联视频时间。只有实际同步记录的事件才能声称与视频对应。

“重新演练这个问题”可以从选定事件创建新会话，保存当时学生的知识状态。重演不会覆盖原始记录，也不把预先知道答案的表现计为首次能力证据。

## 八、接入方式与分阶段实施

保留当前 Vue 3、Element Plus 和 FastAPI。OpenMAIC 的页面采用 React/Next.js，`@openmaic/renderer` 和编辑器有 React 依赖，不能直接作为 Vue 组件使用。

优先借鉴数据结构、提示设计、调度规则、内容生成拆分和校验机制。在 Python 服务层实现对应逻辑，在 Vue 中提供贴合本系统的界面。

### 第一阶段：打通现有课堂模拟

- 修复配置参数传递。
- 接通已有后端会话和报告保存接口。
- 明确真实分析、演示输出与失败状态。
- 统一训练报告、学生报告与教师端使用的评分规则。

主要接入位置：`AIAssistant.vue`、`frontend/src/api/ai.ts`、`backend/app/api/routes/ai.py`、`practice_sessions.py` 和 `ai_model_service.py`。

### 第二阶段：形成核心演练流程

- 增加角色状态和每轮发言调度。
- 加入三种常用场景：答错处理、沉默学生、概念追问。
- 报告携带具体消息或事件证据。
- 问题卡一键进入专项训练，再用新场景复核。

这一阶段是最推荐优先完成的演示版本：上传教案 → 开始虚拟课堂 → 处理学生困惑 → 查看有证据的反馈 → 再练习。

### 第三阶段：扩展备课质量

- 增加教学资源包、大纲编辑与局部重生成。
- 教材知识片段检索与引用。
- 接入两种评审视角。
- 逐步扩展白板与课堂回放。

模型调用沿用当前动态模型管理和用量日志。在新调用链中按任务选择模型、限制每轮调用次数，记录等待时间与失败原因。模型更换不应触发重新生成全部内容。
