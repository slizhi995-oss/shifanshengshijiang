# 英语音频资源中心

配套音频与教学视频直接显示在「AI 教案生成」的 Word 教案下方，生成后与重新打开历史教案时自动读取；没有结果时隐藏配套资源区域。AI 资源中心集中展示精选试讲技巧，并提供打开历史教案的入口。

## 已导入数据

2026-10-22 从项目根目录的 `音频源文件` 导入 943 条 MP3 元数据，覆盖 17 册教材。943 个音频文件均已通过 SHA-256 校验；921 条可自动匹配，22 条按原元数据要求保留待核对。

数据库表：

- `audio_resources`：相对文件路径、音频校验值、教材校验值、单元、活动、页码、审核状态、检索文本和向量。
- `audio_vector_indexes`：索引版本、算法、语料 IDF。
- `audio_lessons`：用户自己的教案、教材来源和匹配结果。

使用本地双语 TF-IDF 稀疏向量和余弦相似度，向量与索引词权重持久化到项目数据库，无额外向量服务或模型 API 依赖。当前索引描述的是原元数据中的教材摘录、活动说明等文本；没有生成听力转写，也不是声音特征向量。

## 匹配与生成

教材教案优先匹配教材 SHA-256。文件校验值不同的扫描/OCR副本，需同时满足学段、标准化册次一致，以及整册至少三个具名教学单元的编号与主题完整对应，才视为同一教材内容；仅册名或单元编号相同不能建立关联。明确出版社不一致或候选有歧义时不自动合并。

Starter Unit、Welcome Unit、Unit、Revision 分别处理。优先使用教材印刷页码（支持 `2-3, 7` 这类非连续页码），不能用不同 PDF 的页序号互相定位。再按听力/阅读等板块和文本相似度排序，最多返回 12 条。

一般英语教案使用年级、学段和课题主题检索。没有可靠匹配时返回空结果。其他学科不展示英语音频；没有其他匹配结果时隐藏配套资源区域。

2026-10-22 修复：高中人教版必修第一至第三册的音频来源 PDF 与原库扫描件的字节校验值不同，但整册单元目录完全对应，现可检索配套音频。实际已生成教案 `News about natural disasters` 匹配 4 条，`Listening / UNIT 1 CULTURAL HERITAGE` 匹配 6 条。北师大版等确实未收录音频的教材仍不混用人教版音频。

匹配缓存同时包含匹配规则版本、索引版本和教案输入指纹。规则更新后会自动重算旧空结果，无需重新生成教案。教案列表搜索也包含教材、单元和章节信息，标题只有 `Listening` 时仍能按 `Cultural Heritage` 找到。

`POST /api/v1/ai/generate` 在生成成功后保存匹配结果，返回 `resource_lesson_id` 和 `audio_count`。生成页直接读取对应教案的匹配结果，并轮询后台视频任务；顶部“配套资源”按钮只在有结果时出现，点击滚动到当前页的资源区域。流式生成在完成时保存教案，并额外返回 `resources` 事件。

导入时自动迁移已有教材教案。迁移只创建资源关联，不重新生成教案；旧 `?lesson=<教材教案ID>` 链接仍能定位。新链接使用 `?resourceLesson=<资源教案ID>`。

## 本地重新导入

在 `backend` 目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/import_audio_library.py
```

默认从项目根目录的 `音频源文件` 读取。导入器要求根目录下仅有一份 `*/音频检索元数据.jsonl`，使用其中的 `relative_new` 解析当前文件位置，不依赖元数据里旧电脑的绝对路径或旧数字教材 ID。

重复导入会更新既有记录、重建索引和教案关联，不重复插入音频。缺失、被修改的文件会标记不可用；`eligible_for_automatic_recommendation=false` 的记录不参与自动匹配。新增音频需同时补充元数据。

自定义位置可在后端环境中设置 `AUDIO_SOURCE_DIR`。命令行 `--source <目录>` 只覆盖本次导入，运行后端时也需设置相同位置。

只需重新匹配已有教案时，可运行 `python scripts/refresh_audio_matches.py`；该命令不重新生成教案，也不重读全部 MP3。

## Docker

`docker-compose.yml` 已将 `./音频源文件` 只读挂载到 `/app/audio_sources`，并配置 `AUDIO_SOURCE_DIR`。部署端需要同步这个目录。首次部署或音频更新后运行：

```sh
docker compose exec backend python scripts/import_audio_library.py
```

音频二进制保留在源目录，不复制到公开 uploads，也不写进数据库。

## 接口与验证

- `GET /api/v1/resources/audio-status`：已接入的音频库概况。
- `GET /api/v1/resources/audio-lessons`：当前用户的已生成教案。
- `GET /api/v1/resources/audio-lessons/{id}`：当前用户的教案正文及对应配套音频（支持从服务端历史恢复到生成页）。
- `POST /api/v1/resources/audio-lessons/{id}/rematch`：重新匹配。
- `GET /api/v1/resources/audio-lessons/{id}/audio/{resource_id}/file`：认证后试听或下载，支持字节范围。

所有教案与文件接口校验归属；音频必须属于该教案的匹配结果且仍可推荐。读取时再次检查路径和文件校验值。浏览器以认证请求获取音频 Blob，再交给原生播放器，切换教案时释放播放 URL。

测试覆盖导入幂等、文件校验、路径越界、版本与单元隔离、待核对排除、生成后关联、历史迁移、用户隔离、下载与 Range 响应。运行示例（临时目录必须是本次新建的目录）：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_audio_resources.py tests/test_lesson_resources.py tests/test_textbook_pipeline.py tests/test_lesson_word.py -q --basetemp=outputs/audio-resource-check-new -p no:cacheprovider
```
