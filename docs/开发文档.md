## 1. 项目概述

### 1.1 项目定位

- **项目名称**：高校师范生试讲智慧管理系统
- **目标用户**：高校师范生（试讲训练）、指导老师（批改与指导）、管理员（教务管理）
- **核心价值**：将“教案质量 + 试讲表现（语音/视觉）+ 课堂互动能力”做成可量化、可解释、可追踪的训练闭环。

### 1.2 AI 应用赛道卖点（建议答辩口径）

- **多模态评价**：教案文本（LLM）+ 语音（ASR 与指标）+ 视觉（姿态/眼神/表情/空间运用）
- **可解释与可追溯**：评分维度清晰，建议可执行；视频可按时间段定位问题
- **过程性评价与成长档案**：支持“成长画像/趋势图”，体现连续训练与能力提升。
- **可部署可扩展**：AI 走 API（通义/DeepSeek/OpenAI-compatible），支持部署到自有服务器。

### 1.3 三端 AI 应用特色总览（展示重点）

#### 1.3.1 学生端（训练与自我提升）

- **AI 备课助手（对话 + 练习报告）**：围绕教案内容进行追问、模拟提问、教学语言优化、生成练习报告与改进清单。
- **AI 教案生成/改写**：根据学段、学科、课题与教学目标生成结构化教案，支持模板与流式输出。
- **AI 教案分析/摘要/改进建议**：对提交的教案进行结构化诊断，给出可执行建议。
- **AI 成长画像/趋势图（必做展示点）**：将多次试讲的教案/视频/互动表现形成能力雷达与趋势折线，突出“过程性评价”。

#### 1.3.2 教师端（批改与诊断闭环）

- **AI 辅助批改**：一键生成评语、建议分与扣分点，老师可编辑后提交，提升批改效率与一致性。
- **多模态试讲诊断**：语音（语速/停顿/语气词）+ 视觉（姿态/手势/眼神/空间运用）维度化报告，支持再次分析。
- **班级/学生画像看板（必做展示点）**：对比分析不同学生的薄弱项与提升速度，支持教学干预与个性化指导。

#### 1.3.3 管理员端（AI 运营与安全治理）

- **[教案指标]**：来自 `lesson_plan_analysis.dimensions.*.score` 与 `overall_score`
- **[视频指标]**：来自 `video_analysis.overall_score`、`speech_rate`、`pause_count`、`filler_word_count`、`gesture_analysis.*`
- **[互动指标]**：来自练习报告（`PracticeReport.response_quality` 等）

## 2. 技术选型与总体架构

### 2.1 前端技术栈

- **框架**：Vue 3 + TypeScript + Vite
- **UI 组件**：Element Plus
- **状态管理**：Pinia
- **路由**：Vue Router
- **图表**：ECharts + `vue-echarts`
- **请求**：Axios
- **API 前缀**：前端 `baseURL: /api/v1`（见 `frontend/src/utils/request.ts`）

### 2.2 后端技术栈

- **框架**：FastAPI
- **鉴权**：JWT（通过 request interceptor 自动带 `Authorization: Bearer <token>`）
- **数据库**：Async SQLAlchemy（开发可 SQLite，生产推荐 MySQL）
- **静态资源**：`/uploads` 挂载（见 `backend/app/main.py`）
- **API Router**：统一挂载到 `/api/v1`（见 `backend/app/main.py`）

### 2.3 AI 与多模态分析

- **教案文本 AI（LLM）**：分析/摘要/改进/评语、教案生成、备课助手（对话 + 报告）
- **视频多模态分析**：语音 ASR（语速/停顿/语气词）+ 视觉分析（姿态/手势/眼神/表情/空间）
- **成本与可靠性**：视频分析结果内包含 `token_usage`（输入/输出 token、音频秒数等），便于运营统计

## 3. 业务角色与权限边界

### 3.1 学生（student）

- 查看导师、作业、提交记录、成绩
- 提交教案/视频；可触发并查看视频 AI 分析
- 使用 AI：备课助手、教案生成

### 3.2 指导老师（instructor）

- 发布作业、管理作业
- 查看学生提交列表；评分/通过/驳回
- 触发/查看视频 AI 分析；使用 AI 辅助批改（教案分析/摘要/改进/评语）

### 3.3 管理员（admin / super admin）

- 批次管理、用户管理、分组分配、公告管理
- 全局监控（按批次/老师/学生筛选）

## 4. 核心业务流程（从布置到成长闭环）

### 4.1 管理员：创建批次与分组

- **创建批次**：`POST /api/v1/semesters`
- **开启/结束批次**：`POST /api/v1/semesters/{id}/start`、`POST /api/v1/semesters/{id}/end`
- **分配导师-学生**：`POST /api/v1/assignments/batch` / `POST /api/v1/assignments/auto-assign/{semester_id}`

### 4.2 老师：发布作业

- **创建作业**：`POST /api/v1/tasks`
- **发布作业**：`POST /api/v1/tasks/{task_id}/publish`

### 4.3 学生：提交作业 + 触发视频分析

- **上传提交**：`POST /api/v1/submissions/upload`（multipart）
- **触发视频 AI 分析**：`POST /api/v1/video-analysis/submissions/{submission_id}/analyze-video`
- **查看分析结果**：`GET /api/v1/video-analysis/submissions/{submission_id}/video-analysis`

### 4.4 老师：批改与审核

- **待批改列表**：`GET /api/v1/submissions/instructor`
- **保存评分**：`POST /api/v1/submissions/{id}/grade`
- **通过/驳回**：`POST /api/v1/submissions/{id}/approve`、`POST /api/v1/submissions/{id}/reject`
- **AI 辅助批改**：`POST /api/v1/ai/analyze`、`/summary`、`/improve`、`/feedback`

### 6.3 数据落库方案（推荐）

当前 `Submission` 已有：
- `lesson_plan_analysis`（JSON 字符串）
- `video_analysis`（JSON 字符串）

为了做“画像/趋势”，建议新增 2 张表（最小可行版本）：

#### 6.3.1 `profile_snapshots`（画像快照表）

- `id` (PK)
- `student_id` (FK users.id)
- `semester_id` (FK semesters.id，可选但强烈建议)
- `computed_from_submission_id`（可选：来源提交）
- `radar_json`（雷达图维度分数：0-100）
- `trend_json`（趋势数据缓存：近 N 次列表）
- `action_items_json`（行动建议 TopN）
- `updated_at`

#### 6.3.2 `practice_sessions`（备课助手练习会话，建议做）

因为你现在的练习会话存浏览器 localStorage，画像无法统计。建议把会话入库：

- `id` (PK)
- `student_id`
- `submission_id`（可选：练习绑定某次教案）
- `title`
- `grade`
- `personality`
- `messages_json`（对话历史，截断保留最近 N 轮也可）
- `report_json`（练习报告）
- `created_at`

> 如果你赶时间：可以先不做 `practice_sessions`，先只用 `Submission` 做画像。

### 6.4 画像计算逻辑（后端 Service）

新增 `backend/app/services/profile_service.py`（建议）

- **[输入]**：student_id + semester_id
- **[读取]**：
  - 该学生本批次所有 `Submission`
  - 解析 JSON 字段：`lesson_plan_analysis`、`video_analysis`
- **[输出]**：
  - `radar_json`：
    - 教案：structure/objectives/key_points/teaching_process/teaching_methods/board_design/language
    - 视频：speech(overall)、gesture(overall)、fluency(语气词/停顿综合)
    - 互动：response_quality 映射分
  - `trend_json`：最近 N 次提交的 `total_score / ai_suggested_score / video_analysis.overall_score ...`
  - `action_items_json`：从历史中找“最低项 + 高频问题”生成行动建议

### 6.7 管理员端 AI 运营看板（必做展示点，规划落地）

#### 6.7.1 已有“用量统计”底座接口

- `GET /api/v1/video-analysis/usage-stats`
  - 返回：`analysis_count`、`total_input_tokens`、`total_output_tokens`、`total_tokens`、`total_audio_seconds`、`console_url`
  - 权限：学生仅统计本人；老师/管理员统计全量

#### 6.7.2 运营指标口径（建议）

- **用量**：按 token/音频秒数统计（来源于 `video_analysis.token_usage` 聚合）
- **失败率**：`failed_count / total_triggered_count`
- **重试成功率**：`retry_success_count / retry_triggered_count`
- **Top 用户/Top 批次**：按 token/音频秒数排序

#### 6.7.3 告警/重试/审计（规划落地）

- **阈值告警**（建议落在系统设置或独立表）： 
  - `daily_token_limit`、`daily_audio_seconds_limit`
  - `failure_rate_threshold`
- **失败重试**：记录每个 submission 的分析尝试次数与最后失败原因
- **审计日志**：记录触发人、触发动作（分析/重试/生成评语）、时间、对象（submission_id）

#### 6.7.4 建议新增运营接口（规划）

- `GET /api/v1/admin/ai-ops/overview?range=`（汇总：用量/失败率/Top 用户/Top 批次）
- `GET /api/v1/admin/ai-ops/failures?range=`（失败列表：可重试）
- `POST /api/v1/admin/ai-ops/retry`（批量重试：submission_ids）
- `GET /api/v1/admin/ai-ops/audit?range=`（审计列表）

- **AI 链路**：教案分析/摘要/改进/评语、视频分析触发与结果获取、AI 备课助手 + 练习报告

- **第 3 周**：AI 运营看板（用量/失败率/告警/重试）

- **上传文件访问**：比赛可先开放 `/uploads`，上线建议鉴权下载
